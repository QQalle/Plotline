# Contributing to Plotline

Thanks for helping improve Plotline.

## Before opening a change

- Search existing issues and discussions.
- Open an issue before undertaking a large public API or architecture change.
- Keep additions grounded in a concrete graphing use case.

## Development

```sh
swift test
```

Changes should include focused tests. Rendering work should also include a reproducible example or snapshot once the snapshot harness lands.

## Pull requests

- Explain the user-facing problem and the chosen behavior.
- Document public API additions.
- Add tests for edge cases and regressions.
- Keep unrelated refactors separate.
- Confirm that no private run data, credentials, or third-party assets are included.

By participating, you agree to follow the project's Code of Conduct.
